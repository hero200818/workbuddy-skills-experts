# 数据复盘口径

复盘的目的不是写述职报告，是回答一个问题：**下一篇要改哪一个变量。**

## 一、台账数据列

```
# | 标题 | 选题 | 状态 | 时间 | 阅读 | 点赞 | 在看 | 评论 | 分享 | 完读率 | 涨粉
```

- `状态`：`草稿箱` / `已群发` / `已删`
- `时间`：发布时刻，格式 `YYYY-MM-DD HH:MM`（逾期催办按它算 24h/72h）
- 空值一律写 `—`，**不要写 0**。0 是"确认没有人点赞"，`—` 是"还没看"

## 二、五个派生指标（都从上面算，别再新增原始列）

| 指标 | 算法 | 它回答什么 |
|---|---|---|
| 点赞率 | 点赞 ÷ 阅读 | 内容有没有让人"认可" |
| **在看率** | 在看 ÷ 阅读 | 有没有人愿意**替你在朋友圈站台**（公众号最贵的动作） |
| **评论率** | 评论 ÷ 阅读 | 有没有话想说（争议度、代入感） |
| 分享率 | 分享 ÷ 阅读 | 有没有实用价值（"存下来以后用"） |
| 涨粉率 | 涨粉 ÷ 阅读 | 新读者认不认这个号 |

**完读率**直接用后台的"阅读完成率"，不要自己估。

```bash
python scripts/gzh.py retro              # 汇总台账里所有已回填的篇目
python scripts/gzh.py ledger --audit     # 哪些该回填还没填
```

## 三、回填时点

| 时点 | 为什么要它 |
|---|---|
| **24h** | 决定这篇有没有进推荐池，是最关键的一次读数 |
| **72h** | 长尾是否起来，能不能二次转发 |
| 7 天（可选） | 判断这是"一篇爆款"还是"一条可持续的题材线" |

**发布后 24 小时内必回填一次**，否则 72 小时的数据会掩盖 24 小时的爆发曲线，
你就分不清是"推了一把"还是"慢慢涨的"。

## 四、归因：三看

一篇数据不好，只有三个可能的位置，按顺序排查：

1. **看点击率**（阅读 ÷ 曝光，后台有"公众号会话打开率"）
   - 低 → 标题与封面的问题，去改标题，不要动正文
2. **看开头留存**（后台阅读来源 + 完读率）
   - 完读率低但打开率高 → 正文前三段的问题，去改开头钩子
3. **看互动**（评论率、在看率）
   - 读完但不互动 → 结尾没有给动作，或观点太温

**一次只改一个变量。** 标题和开头同时改，下次数据变好也不知道是谁的功劳。

## 五、判断标准

行业绝对值不可靠（不同号、不同粉丝结构差异极大）。**用你自己的基线**：

- 前 3 篇作为基线，取中位数
- 第 4 篇起，与基线比：高于基线 30% 算"这次做对了"；低于 30% 算"这次退步"
- 连续 3 篇低于基线 → 不是单篇问题，是选题方向或账号定位出了问题

样本不足 3 篇时，任何结论都只是猜测。脚本会自己提示"样本不足，别当真"，照实转述。

## 六、三个常见误判

| 误判 | 实情 |
|---|---|
| 阅读高就是成功 | 若阅读来自"看一看"推荐而涨粉为 0，说明内容被消费但账号没被记住 |
| 评论多就是好 | 要看评论是"共鸣"还是"对骂"。对骂的评论率高但不涨粉 |
| 转发少就是内容差 | 情绪型内容转发少、在看多，是正常的；实用型才靠转发 |

## 七、复盘产出格式

```
【本期数据】
篇目：{标题}
24h：阅读 {} 点赞 {} 在看 {} 评论 {} 分享 {} 完读率 {} 涨粉 {}
派生：点赞率 {}% 在看率 {}% 评论率 {}% 分享率 {}%

【归因】
点击率 {}（基线 {}）→ 判断：标题{正常/偏弱}
完读率 {}（基线 {}）→ 判断：开头{正常/劝退}
评论率 {}（基线 {}）→ 判断：结尾{有钩子/没钩子}

【下一篇改哪一个变量】
只改：{标题 / 开头 / 结尾}
理由：{一句话}
【复用】这篇里值得留下的写法：{一句具体的写法，不是"情感真挚"这种空话}
```
