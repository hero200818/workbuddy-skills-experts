# 公众号配图处理

生图 → 去水印 → 压到合规 → 核查。四步，每步都有明确的失败模式。

## 什么时候用

- 拿到 ImageGen / Midjourney 出的图，底部带 AI 水印，要裁掉
- 上传言序报 `ret:10001`，或公众号后台说图片过大
- 发布前要确认封面和正文图都在体积上限内

## 三个坑（不记住必翻车）

### 1. 水印位置不固定

不是每次都在底部 50–65px。同一个模型、同一天，两张图的水印高度能差 24px：
实测第 1 篇裁 `72px` 就干净，第 3 篇要裁到 `96px`。裁少了水印留着，裁多了切主体。

**做法**：先裁 `72`，打开成图看右下角有没有残留，有就加 8px 重跑。**不许按固定值盲裁就交付。**

### 2. 两套体积上限

| 类型 | 上限 | 为什么 |
|---|---|---|
| 封面 | 2MB | 公众号封面单独校验 |
| 正文图 | 1MB | 微信正文图压缩通道更窄 |

脚本按文件名判断：名字含 `cover` 或 `封面`（不分大小写）走封面档，其余走正文档。
**按一套压，另一套必超。** 超限时言序报的是 `ret:10001`，看起来像"图坏了"，其实只是大。

### 3. `--dir` 是全量重刷

`--dir` 指向父目录会把目录下所有源图重跑一遍，**覆盖同名成品**。如果历史各篇的源图都堆在同一个 raw 目录，一跑就把已发布文章的成品图全刷掉。

**做法**：一个选题一个子目录，`配图/raw/选题28/`。跑之前先 `ls` 确认只有本篇的图。

## 用法

```bash
# 处理源图：裁底去水印 + 压到双档以内
python scripts/img_tool.py process --dir 配图/raw/选题28 --out 配图 --trim 96

# 上传前核查成品
python scripts/img_tool.py check --dir 配图
```

参数：

| 参数 | 默认 | 说明 |
|---|---|---|
| `--dir` | 必填 | `process` 填源图目录，`check` 填成品目录 |
| `--out` | 同 `--dir` | 成品输出目录 |
| `--trim` | 72 | 从底部裁掉多少像素，**按图实测** |
| `--quality` | 85 | 起始 JPEG 质量，超限自动降到 80/72/65/58/50/42 |
| `--suffix` | `_clean` | 成品后缀，`a.png` → `a_clean.jpg` |
| `--cover-kb` | 2000 | 封面档上限 |
| `--body-kb` | 1000 | 正文档上限 |

退出码：`0` 全部合规 · `1` 有超限或缺图 · `2` 缺 Pillow。

## 验收

跑完必须同时满足：

1. 输出末行是 `✓ 全部 N 张符合双档限制`
2. **打开每一张成品图看右下角**，确认没有水印残留、主体没被切
3. 张数 = 源图张数（少了说明有图被当成成品跳过了）

第 2 条不能省。脚本只能告诉你体积合规，看不出水印还在。

## 环境

需要 Pillow：`python -m pip install Pillow -i https://pypi.tuna.tsinghua.edu.cn/simple`

不读任何项目配置文件，四个默认值都在命令行上，换个项目直接能用。
