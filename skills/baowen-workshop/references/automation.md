# 自动化运营配置

当用户要求"自动运营/日更/定时出稿/周报复盘"时，按本文件配置定时任务。自动化范围是**内容生产+复盘**，最后一步"点发布"由用户手动完成（不登录用户账号）。

## 自动化循环（本号实际运行表）

| 时间 | 任务 |
|---|---|
| 每天 19:35 | 写当晚微头条成稿并自动存后台草稿，用户19:55检查、**20:00黄金档发布** |
| 每天 12:30 / 18:30 / 21:30 | 读最近几小时新评论，分类并生成可直接复制的回复话术 |
| 每天 15:37 | 读昨日后台真实数据登记台账，监测是否触发追爆 |
| 周一/三/五 20:30 | 把本周赞最高微头条扩写成1200-1500字首发长文草稿 |
| 周日 20:10 | 读本周后台数据复盘，找Top1爆款，调题材权重，排下周7条选题 |

## 配置要点

- query 必须自包含：定时任务在全新会话运行，人设细节（年龄/职业/收入/家庭）和方案文件路径必须写进 query，不能依赖历史对话。
- 方案文件路径：`<项目目录>/头条号激活执行方案.md`，query 里要求任务触发时先读它。
- 不写任何账号密码/cookie/token；不代替用户登录发布。
- 栏目固定：周一/三=职场吐槽，周二=钱与账单，周四=人情往来，周五=外卖日常，周六=温情治愈，周日=纯提问帖。
- 成稿规范：**100-150字（不是200-300，老号实测106字最爆）**、无标题、一条一个生活切片、钩子开头、生理反应细节、结尾AB提问、2-3个白名单标签、配图建议3张、提醒勾选首发。爆款参数见 references/proven-viral-cases.md。

## 智能化记忆层：运营台账

所有自动任务共享一个台账文件（`<项目目录>/运营台账.md`），它让系统越跑越聪明：

- **人设档案**：锁定收入、房租、家庭等细节，每次出稿前核对，防止人设穿帮。
- **已发选题台账**：出稿前先读，避开最近写过的题材；写完新稿登记回去，不重复。
- **题材权重表**：哪类内容爆过就自动加星，排选题时优先高权重题材；连续扑街的题材降权。
- **评论区待挖选题**：周复盘时把用户评论里的高频问题录入，转化为下周选题。
- **本周数据表**：用户每周日填实际赞/阅读，任务据此判断爆款并更新权重。

闭环：出稿读台账 → 登记新选题 → 用户发完填数据 → 周复盘更新权重 → 下次出稿优先高权重题材。

## 双轮内容策略（基于真实粉丝画像，见 fan-insights.md）

- **A轮拉新**：日更微头条/长文写"周哥普通人故事"（钱账/外卖/人情），抢公域推荐流量。
- **B轮激活**：每周2条写给现有40-60岁粉丝看的内容（年代回忆/民生人情/健康感受，不碰时政），目标是唤醒37.8%活跃粉丝的评论互动。
- 周复盘排期时：A轮5条+B轮2条分配到一周7天。

## 扩展自动化

- 用户要求数据监测时：每日/每周用 web.fetch 重新抓账号主页，对比粉丝数和爆款变化，出现爆款时自动提示"追更同结构"。
- 用户要求多账号矩阵时：每个账号一套独立定时任务，query 中写清各自账号URL与人设。
