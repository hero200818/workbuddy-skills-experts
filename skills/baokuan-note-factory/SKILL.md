# 爆款笔记工厂 · 小红书诊断量产一体机（baokuan-note-factory）

> 一句话：把一个小红书账号从"数据"变成"诊断"再变成"可发布的内容弹药库"。

五步工作流（数据采集 → 诊断计算 → 策略制定 → 内容量产 → 复盘迭代），每步有明确输入输出。

## 总原则

- **数据先行**：所有结论必须挂在具体数字上；缺的数据如实标注来源限制，不编造。
- **凭据安全**：涉及登录后台时，必须由用户本人在浏览器完成登录，AI 全程不接触账号密码/验证码/Cookie。
- **只读优先**：诊断阶段只读取；写操作（改定时、存草稿）仅在用户明确要求时执行，且绝不点"发布"。
- **交付物是文件**：报告、发布包写成 md 文件交付，不整段贴聊天。

## 第 1 步 · 数据采集

1. 引导用户登录创作服务平台（Web 端），抓取：首页数据总览、数据看板-内容分析（逐篇笔记：曝光/观看/封面点击率/赞/藏/评/涨粉）、粉丝数据（性别/年龄/城市/兴趣）。
2. Web 端拿不到的维度（观看来源占比、粉丝活跃时段、APP 端画像明细、涨粉TOP笔记、忠实互动粉名单）→ 请用户提供 APP 数据中心截图，逐张读图提取。
3. 双端数据逐项交叉验证，一致则标注"双源支撑"；不一致以更新口径为准并说明。
4. 平台不展示的（如新增粉丝数过少导致"暂无数据"）如实记录，作为"涨粉太慢"的佐证而非缺口。

## 第 2 步 · 诊断计算

把逐篇笔记数据整理成 JSON（格式见 scripts/metrics.py 头部注释），运行：

```
python scripts/metrics.py notes.json
```

输出：总曝光/点击率均值/互动率/每千曝光涨粉/零评论占比/零涨粉占比/选题分组对比/Top&Bottom 榜。

对照 references/benchmarks.md 的基准表判定账号卡点，重点看三组矛盾：
- 曝光有但互动率低 → 内容留不住人（标题/封面/前3秒问题）
- 互动有但不涨粉 → 缺关注理由（人设/主页/结尾引导问题）
- 新笔记差但旧笔记长尾好 → 方向跑偏，旧资产指路

## 第 3 步 · 策略制定

1. **定位修正**：用"涨粉TOP笔记的共同点 + 粉丝兴趣TOP + 观看来源结构"三源交叉，找出账号真实人设（常与自我定位不同）。
2. **选题三档分层**：第一梯队（涨粉证据强→每周2篇加码）/ 第二梯队（互动好→每周1-2篇）/ 砍掉（0涨粉0互动→停更）。
3. **P0/P1/P2 优先级清单**：P0=本周零成本高收益改动（发布时间、标题模板、评论钩子）；P1=两周内（激活死粉、合集、降频提质）；P2=本月（活动报名、对照实验）。
4. 发布时间对齐"观看时段"峰值前 1-2 小时。

## 第 4 步 · 内容量产（发布包）

按 references/pack-template.md 的固定格式产出发布包 md。每篇必须含 6 件套：
1. 标题：≤20 字，"痛点/悬念+数字+人群指向"，书名保留以吃搜索流量
2. 封面制作单或成品图
3. 前 3 秒口播悬念句（完播率短板时必配）
4. 图文版正文（含结尾评论钩子+关注引导+话题标签）
5. 置顶评论（发布后立即自贴，垫热度）
6. 数据追踪表行

批量配图用脚本（iOS 液态玻璃风：渐变底+光斑+磨砂卡片+高光描边+投影）：

```
python scripts/make_covers.py cover_spec.json
```

spec 格式见脚本头部注释；每篇 6 图结构：封面钩子→故事开始→最戳一幕→读懂一刻→最狠一句→互动卡。

排期规则：隔日一篇、全部定时同一高峰时间；小说/故事线 ≥60% 时穿插情绪线做对照实验；蹭节日/剧集热点排期。

## 第 5 步 · 复盘迭代

设定复盘节点（首篇满 7 天起）。判定标准：
- 主力线确认：A 线平均涨粉 > B 线 → 下周起 A 线占比 ≥70%
- 标题法生效：新笔记点击率均值 ≥5% → 永久弃用旧模板
- 完播率 <15% → 视频压到 60 秒内，悬念句上封面
- 评论数 ≥10 的篇目 → 评论区问题做成下一篇选题（内容永动机）

## 红线

- 不承诺涨粉数值，只给先行指标（点击率/完播率/互动率）→滞后指标（涨粉）的因果链
- 报告中标注哪些是平台官方数据、哪些是经验基准、哪些是定性判断
- 小样本（<30 篇）结论标注置信度，单篇波动不作依据
