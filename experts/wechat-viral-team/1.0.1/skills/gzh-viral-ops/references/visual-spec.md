# 配图规范（视觉）

配图不是装饰，它决定两件事：**读者信不信**、**能不能上传成功**。

## 一、数量与位置

| 位置 | 数量 | 作用 |
|---|---|---|
| 封面 | 1 | 决定信息流里的点击，也决定转发时的缩略图 |
| 开头后 | 1 | 承接第一段情绪，给读者一个"喘气点" |
| 中段 | 1–2 | 在转折处换气，避免长文疲劳 |
| 结尾前 | 1 | 收束情绪，别放在最后一行之后 |

一篇 1500–2000 字，**4–5 张**最舒服。少于 3 张显空，多于 6 张像拼贴。

## 二、两档体积（硬约束）

| 用途 | 上限 | 超了会怎样 |
|---|---|---|
| 封面 | **≤ 2MB** | 上传失败或自动压缩变形 |
| 正文图 | **≤ 1MB** | 言序返回 `ret:10001`，整篇发不出去 |

推荐实际值：封面压到 **150–300KB**，正文图 **80–250KB**。这样即使平台再压一次，
画质也还撑得住。压得再小（<40KB）会糊，得不偿失。

```bash
# 处理：去水印 + 压到两档以内，成品写 _clean.jpg
python scripts/gzh.py assets --dir 配图 --trim 72 --cover-kb 2000 --body-kb 1000

# 核查：只查成品，全绿才发
python scripts/gzh.py assets --dir 配图 --check
```

## 三、原图的水印必须裁掉

ImageGen 出的图右下角带「AI生成 WORKBUDDY」水印，位置**不固定**：多数在底边往上 50–65px，
少数图更高（实测有要裁到 95px 才干净的）。
统一裁 **72px** 作下限；若裁完仍见残字，加到 **96px**。

裁完**必须看一眼**。按固定值盲裁，是水印漏到线上的主要原因。

**出图即裁，不要留到最后。** 留到发布的代价是：稿子里的 `src` 全指向带水印的图，
要么临时改名，要么把水印发出去。

目录约定：

```
配图/raw/          ← ImageGen 原始输出（带水印，不入库、不进 git）
配图/*_clean.jpg   ← 成品（去水印 + 压过体积，入库、进 git）
```

## 四、提示词模板

```
{风格} illustration of {具体场景，含 1 个可辨识物件}, {人物与动作}, {色调},
no text, no letters, no watermark, clean composition, editorial style
```

| 要素 | 要求 | 反例 |
|---|---|---|
| 风格 | 扁平插画 / 暖色线稿 / 极简编辑插画，全篇统一 | 一张写实一张卡通 |
| 场景 | 具体到"地铁车厢里一个拎菜的老人" | "关于老年人的插图" |
| 人物 | 给动作和姿态，不给正脸特写 | "一位老人" |
| 文字 | **必须写 `no text, no letters`** | 让模型画"写着字的告示牌" |
| 色调 | 与账号调性一致（暖、克制） | 高饱和撞色 |

**重要**：图里一旦出现文字，模型渲的是乱码，放大就能看出来。所以提示词里明确禁文字，
画面里用物件和姿态表达，不靠图内文字。

## 五、封面设计

- 比例按平台要求（公众号封面 2.35:1，正方形版本也备一张）
- **封面上的字最多 6–8 个**，且必须是标题里最狠那半句，不能是完整标题
- 字要压在深色块或留白上，别压在人脸和细节上
- 若标题已经很长，封面**不放字**，只留画面 —— 信息流里标题就在图下方

## 六、验收清单

- [ ] 5 张图都去了水印（放大右下角看不到字）
- [ ] 封面 ≤2MB，正文图 ≤1MB，且都不小于 40KB
- [ ] 图里没有乱码文字
- [ ] 稿子里 `img src` 指向 `配图/*_clean.jpg`，不是 `配图/raw/*.png`
- [ ] 全篇风格统一（同一套笔触、同一组色调）
- [ ] 每张图都在它该在的位置（转折处，不是随机插入）
